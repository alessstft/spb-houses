# Инфраструктура и стек проекта «Дома Санкт-Петербурга»

## 1. Общая схема

Проект состоит из двух частей, которые работают в разных местах:
- **Подготовка данных** выполняется один раз на компьютере разработчика: из выгрузки ГИС ЖКХ получаются компактные файлы данных.
- **Сайт** — статическое веб-приложение на GitHub Pages. Вся логика (поиск, карточка, выгрузка Excel) выполняется в браузере пользователя.

Сервера приложений и серверной СУБД нет.

```
ГИС ЖКХ (dom.gosuslugi.ru)
   │  архив «Сведения по ОЖФ», .tar.gz, ~3,3 ГБ (вся РФ) — скачивается вручную
   ▼
Компьютер разработчика (Windows + WSL Ubuntu)
   │  tar → 8 CSV по Санкт-Петербургу (~1,7 ГБ, 3 566 939 строк)
   │  scripts/prepare.sh (bash + awk)
   │     ├─ houses.awk   → data/spb_houses.csv        (51 532 дома, 18 МБ)
   │     └─ premises.awk → data/premises/p_0…p_f.csv  (16 файлов, 13–24 МБ)
   │  git commit / push (VS Code)
   ▼
GitHub: репозиторий alessstft/spb-houses (код + данные)
   │  автоматическая сборка GitHub Pages
   ▼
GitHub Pages: https://alessstft.github.io/spb-houses/  (раздача статических файлов)
   │
   ▼
Браузер пользователя (ноутбук / телефон)
   ├─ HTML/CSS/JS-модули сайта
   ├─ библиотеки с CDN cdnjs (PapaParse, SheetJS, ExcelJS), шрифт Google Fonts
   ├─ данные: spb_houses.csv при открытии, p_X.csv по запросу
   ├─ IndexedDB: сохранённый пользовательский файл
   └─ внешние ссылки: Яндекс.Карты
```

## 3. Хранение данных («БД»)

Серверной СУБД в проекте нет. Роль базы данных выполняют **файлы CSV** в репозитории: они раздаются GitHub Pages как статика и читаются браузером. Такой подход выбран потому, что данные открытые, обновляются редко, а пользователям нужен только просмотр.

### 3.1. Логическая модель

```
ДОМ (spb_houses.csv)                    ПОМЕЩЕНИЕ (premises/p_X.csv)
─────────────────────                   ───────────────────────────
PK  GUID дома          1 ─────────── N  FK  GUID дома (строка-заголовок «#GUID»)
    Адрес                                   Статус
    Статус (МКД)                            № помещения
    Кадастровый номер                       № комнаты (у ЧКВ)
    УО, площади, …                          Кадастровый номер
    счётчики КВ/НЖ/ММ/ОИ/ЛК/ЧКВ/ERR         ID-FIAS

Внутри помещений: КВ (квартира) 1 ── N ЧКВ (комнаты), связь по № помещения
```

### 3.2. Исходная таблица ГИС ЖКХ (вход, в репозиторий не входит)

Формат: CSV, разделитель `|`, UTF-8, 23 столбца, одна строка = помещение или комната. Строка без типа помещения — запись самого дома. Используемые поля:

| № | Поле | Использование |
|---|---|---|
| 1 | Адрес ОЖФ | адрес дома |
| 3 | Глобальный уникальный идентификатор дома по ФИАС | GUID ФИАС |
| 4 | Код ОКТМО | ОКТМО |
| 5 | Способ управления | УО, ТСЖ, ЖСК, НУ |
| 6 | ОГРН организации, осуществляющей управление домом | ОГРН УО |
| 8 | Наименование организации, осуществляющей управление | УО |
| 9–10 | Тип дома, Состояние | карточка |
| 11–12 | Общая площадь дома, Жилая площадь в доме | карточка |
| 16 | Тип помещения (блока) | правило статуса |
| 17 | Дата сноса объекта | карточка |
| 18–19 | Номер помещения, Номер комнаты | номер в реестре, ЧКВ |
| 20 | Кадастровый номер | правило статуса, реестр |
| 21 | Глобальный уникальный идентификатор дома | **ключ дома**, ID-FIAS для МКД |
| 22 | Глобальный уникальный идентификатор помещения | ID-FIAS для КВ, НЖ, ОИ |
| 23 | Глобальный уникальный идентификатор комнаты | ID-FIAS для ЧКВ |

### 3.3. `data/spb_houses.csv` — таблица домов

Формат: CSV, разделитель `|`, UTF-8, первая строка — заголовок, одна строка = дом. Объём: 51 532 строки, 18 МБ. Файл строит `houses.awk`.

| Столбец | Описание |
|---|---|
| Адрес | полный адрес из ГИС ЖКХ |
| Статус | МКД (есть строка дома) |
| Кадастровый номер | кадастровый номер здания |
| GUID дома | **первичный ключ**, связь с помещениями |
| GUID ФИАС | идентификатор дома в ФИАС |
| ОКТМО | код территории |
| Способ управления | УО / ТСЖ / ЖСК / НУ |
| ОГРН УО | ОГРН управляющей организации |
| Управляющая организация | полное наименование |
| Тип дома | многоквартирный / жилой |
| Состояние | исправный / ветхий / аварийный |
| Общая площадь | м² |
| Жилая площадь | м² |
| Дата сноса | если есть |
| Помещений всего | уникальные помещения по GUID |
| КВ, НЖ, ММ, ОИ, ЛК, ЧКВ, ERR | количество по статусам |
| Квартир с комнатами | число квартир, где учтены комнаты (ЧКВ) |

### 3.4. `data/premises/p_0.csv … p_f.csv` — помещения

Формат: текст UTF-8, разделитель `|`. Файлы строит `premises.awk`. Объём: 3 566 939 записей, 16 файлов по 13–24 МБ.

Структура файла — группы по домам:
```
#<GUID дома>
СТАТУС|№ помещения|№ комнаты|Кадастровый номер|ID-FIAS
СТАТУС|№ помещения|№ комнаты|Кадастровый номер|ID-FIAS
…
```

**Шардирование:** дом попадает в файл по первому символу своего GUID (`0–9`, `a–f`), то есть 16 файлов примерно равного размера. Поэтому при открытии дома браузер загружает только один файл, около 1/16 данных, и хранит его в памяти до закрытия страницы.

**Статусы помещений:**

| Статус | Правило |
|---|---|
| МКД | тип помещения пустой (запись дома) |
| КВ | жилое, есть кадастровый номер |
| НЖ | нежилое, есть кадастровый номер |
| ММ | машино-место |
| ОИ | нежилое, нет кадастрового номера |
| ЛК | правило не задано заказчиком |
| ЧКВ | жилое, нет кадастрового номера, есть номер комнаты |
| ERR | не подошло ни одно правило |

ID-FIAS: у МКД — GUID дома, у ЧКВ — GUID комнаты, у остальных — GUID помещения.

### 3.5. Хранилище браузера (IndexedDB)

| Параметр | Значение |
|---|---|
| База | `spb-houses` |
| Хранилище | `files` |
| Ключ | `last` |
| Значение | `{ buffer, name }` — последний файл, открытый пользователем вручную |

Используется только как запасной источник: если данные с сайта не загрузились, показывается сохранённый файл.

### 3.6. Выходной документ — реестр Excel

Файл формируется в браузере по кнопке «Скачать реестр помещений»:
- листы «Дом», «Помещения», «Собственники», «Реестр», «Повестка» (по шаблону заказчика, заполнен лист «Помещения»);
- столбцы A–N: статус, адрес, № помещения, площадь, кадастровый номер, доля ОИ, …, тип помещения, этаж, ID-FIAS, КадНомЗдания;
- столбцы P–S: расчёт по статусам формулами Excel (количество, площадь, % площади), плюс формула доли ОИ по каждому помещению;
- порядок строк: МКД / КВ / НЖ / ММ / ОИ / ЛК / ЧКВ / ERR.

## 5. Как работает сайт при открытии

1. Браузер загружает `index.html`, стили, `main.js` и связанные модули, библиотеки PapaParse и SheetJS.
2. `main.js` запрашивает `data/spb_houses.csv` (18 МБ, по сети передаётся в сжатом виде) и строит в памяти модель `HouseTable`.
3. Поиск выполняется в памяти браузера по нормализованным адресам и кадастровым номерам.
4. При открытии вкладки «Помещения» или выгрузке реестра загружается один файл `data/premises/p_X.csv` и кэшируется в памяти.
5. При выгрузке реестра по требованию подгружается ExcelJS, файл собирается в браузере и скачивается.

## 6. Обновление данных

1. Скачать новый архив «Сведения по ОЖФ» с ГИС ЖКХ.
2. Извлечь файлы Санкт-Петербурга: `tar -xzvf Сведения*.tar.gz --wildcards "*Петербург*"`.
3. Запустить `bash scripts/prepare.sh <папка с CSV>`.
4. Закоммитить и отправить папку `data` (Commit → Sync). GitHub Pages опубликует обновление автоматически.


## 7. Безопасность и ограничения

- **Данные:** только открытые данные ГИС ЖКХ, персональных данных собственников нет. Секретов, ключей и паролей в проекте нет.
- **Серверной части нет**, поэтому нет и серверных уязвимостей. Сайт только читает статические файлы.
- **Ограничения:**
  - нет площадей помещений (их нет в ГИС ЖКХ; источник — Росреестр);
  - нет редактирования данных и разграничения доступа;
  - размер данных ограничен лимитами GitHub: файл до 100 МБ, опубликованный сайт до 1 ГБ. Текущий объём около 250 МБ.
